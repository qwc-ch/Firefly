前几天去学校机房做调查问卷。本以为就是点几十道选择题的事，结果这次机房之行信息量有点大，值得记录一下。

## 机房电脑：4 核 4G

先吐槽一下机房电脑的配置：4 核 4G。

开机要等半天，随便开个网页风扇就开始起飞。2026 年了，这配置属实有点复古。在这种机器上干活的第一个感受就是：卡。

但问卷总得做。

## 问卷：为什么问厕所安不安全

做问卷的时候，我看到有一题，大意是「学校的厕所安不安全」。

？？？我填的是调查问卷，不是厕所安全测评。这题跟其他题八竿子打不着，我想了半天也没想明白最后能统计出个什么结论。

## 不到时间不给走

做完想走，不让走，不到时间不给走。

好，那就坐着。与其干瞪眼，不如干点别的——比如，在这台 4 核 4G 的电脑上装个 Node.js。

## 第一步：官网一个都打不开

计划很美好，现实是：Node.js 官网打不开，GitHub 打不开，连微软的网站也打不开。

校园网的神秘力量，我至今没搞懂它的封锁逻辑。

搜了一圈，搜出来一个镜像站：Node.js 中文网。进去一看，版本不全，最新的也只有 Node 22。

凑合用，22 够了。

## 第二步：下错了一回

第一次下载没看仔细，下成了 32 位（x86）的版本。

现在的电脑基本都是 64 位的，装 32 位虽然也能跑，但完全没必要。重新下了一个 x64 安装包，这次对了。

> 教训：下载安装包之前，先看清楚位数。

## 第三步：给 npm 和 pnpm 配镜像

刚经历过「网页都打不开」的网络，我深知直接 `npm install` 会是什么下场。装好 Node 之后第一件事就是换源：

```bash
npm config set registry https://registry.npmmirror.com
```

pnpm 也换上：

```bash
pnpm config set registry https://registry.npmmirror.com
```

这下装依赖的速度总算像样了。

## 第四步：项目从 Gitee 下载 zip

项目代码怎么弄下来？GitHub 刚才已经验证过了：打不开。

所以直接换了个思路：上 Gitee，找到项目，Download ZIP。解压、装依赖、启动，一套流程走完，项目总算是跑起来了。

回头想想有点好笑：GitHub 打不开，Node 官网打不开，最后是镜像站和 Gitee 救的场。在机房这种网络环境下，镜像站和国内源就是救命稻草。

## 总结

这次机房之行学到的：

- 机房电脑虽然只有 4 核 4G，但跑个项目还是没问题的
- 官网打不开的时候，先找镜像站
- 下载安装包之前，看清楚 x64 还是 x86
- npm / pnpm 记得配国内镜像
- GitHub 下不动的时候，Gitee 的 Download ZIP 也很好用
- 做问卷剩下的时间，装个环境跑个项目，就不算白等

至于学校的厕所到底安不安全——问卷没告诉我，我也没去验证。
